# Хаб фичи

Разреши символьную ссылку на этот файл; корень kit (`KIT`) находится на два каталога выше его папки. Прочитай `KIT/AGENTS.md`, `KIT/agents/roles/tech-lead.md`, применимые инструкции целевого проекта (`PROJECT`) и `KIT/agents/workflows/feature-hub.md`.

Работай как управляющая сессия: PRD → карта задач → задание сессии → результат → обновление карты. Код задач здесь не реализуй. Сессии открывает пользователь; хаб собирает результаты по запросу, без фонового наблюдения и обязательных дополнительных агентов.

Установи общую папку фичи (`FEATURE`) в Obsidian по [правилам хранения](references/artifacts.md). При неоднозначном проекте/ID или пути внутри vault уточни только недостающее. Для существующего хаба сначала прочитай его навигацию и продолжи текущую структуру; не создавай рядом второй реестр и не мигрируй заметки автоматически. Если прежний хаб хранится только в проекте, согласуй путь полной копии в Obsidian до передачи следующей задачи. Внешняя папка не расширяет sandbox: при недоступной записи используй штатное согласование доступа, не создавай молча другую основную копию.

Перед созданием или обновлением артефактов прочитай [форматы и правила владения](references/artifacts.md). Вызов этого skill разрешает необходимые артефакты сценария, но не изменение исходных PRD, регистрацию Git, создание worktree, коммит, push или публикацию в Jira. Git и сервисы подключай только по необходимости, по `KIT/agents/integrations.md`.

Примеры запросов:

- `$feature-hub Разбери PRD PATH и организуй реализацию в общей папке PATH`.
- `$feature-hub Собери статус FEATURE по результатам сессий`.
- `$feature-hub Подготовь задание следующей доступной задачи FEATURE`.
- `$feature-hub В FEATURE появилась новая редакция PRD: PATH; оцени влияние`.
