# Проверка задачи или фичи

Разреши символьную ссылку на этот файл; корень kit (`KIT`) находится на два каталога выше его папки. Прочитай `KIT/AGENTS.md`, `KIT/agents/roles/qa.md`, применимые инструкции проекта (`PROJECT`) и `KIT/agents/workflows/verify-feature.md`.

Определи охват: одна задача или сквозные критерии фичи, их источники и фактические версии компонентов. Для задания хаба прочитай его редакцию, карту, контракты и [форматы артефактов](../feature-hub/references/artifacts.md). Новая сессия QA пишет отдельный отчёт, не журнал исполнителя или карту. Для обычной задачи хаб и Jira не обязательны.

Запрос проверки не разрешает исправлять код, менять критерии, устанавливать зависимости или публиковать результаты во внешние сервисы. Не переключай ветки и не подготавливай новые worktree без согласования. Проверки выполняй в доступной копии нужной версии; недоступность выполнения отмечай отдельно от найденных дефектов.

Полный отчёт сохрани в `FEATURE/checks/CHECK_ID.md` в Obsidian; без хаба установи папку задачи в Obsidian по формату артефактов. Проектная ссылка/копия в `.engineering-kit/runs/CHECK_ID/qa.md` допустима только после проверки локального исключения Git. Выбери свободный CHECK_ID, прошлый отчёт не перезаписывай. Вызов skill разрешает этот артефакт, но не расширяет sandbox; при недоступной записи используй штатный запрос доступа, сообщи о незавершённом сохранении и верни результат в диалоге. Для структуры используй [шаблон](assets/report.md), заполняя только применимые поля.

Примеры: `$verify-feature Проверь задачу по PATH_TO_BRIEF`; `$verify-feature Проверь сквозные критерии FEATURE на указанном стенде`.
