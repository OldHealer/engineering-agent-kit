# Исследование дефекта

Разреши символьную ссылку на этот файл; корень kit (`KIT`) находится на два каталога выше его папки. Прочитай `KIT/AGENTS.md`, роль tech-lead и `KIT/agents/workflows/investigate-bug.md`; пути kit разрешай от `KIT`. Прочитай применимые инструкции целевых репозиториев. Работай последовательно, читая нужные роли перед их использованием.

До сохранения отчёта установи папку задачи в Obsidian по `KIT/skills/feature-hub/references/artifacts.md`. Там сохраняется полный отчёт; проектные ссылки/копии допустимы только локально под `.engineering-kit/` после проверки исключения Git. Недоступность Obsidian отмечай как незавершённое сохранение, не заменяй его молча проектной копией.

При доступном `kit-git` регистрацию и подготовку выполняй через discover/init/prepare по `KIT/agents/integrations.md` вместо shell-команд ниже. До создания worktree согласуй репозиторий и ревизию; при уже данном согласии не спрашивай повторно. Очистка — через skill workspace-cleanup. Это не разрешает исправление кода или публикацию.

В режиме current исследование текущей ветки можно выполнять в исходной копии на чтение, без создания worktree. Если для воспроизведения нужна другая ревизия, предложи отдельный worktree. Исправление после согласования выполняется по plan-feature с учётом режима проекта; исходная current-папка не очищается как worktree.

1. Установи проект, симптом, ожидаемое поведение и исследуемую ревизию. Для Jira, Confluence и PR прочитай `KIT/agents/integrations.md` и используй доступные MCP kit. Публикация вывода в комментариях требует явного поручения. При отсутствии регистрации подключи проект через `python3 KIT/scripts/kit.py init --project PROJECT`, уточнив состав при неоднозначности.
2. Если нужна воспроизводимая копия на коммите, создай уникальный ID и выполни `prepare --project PROJECT --id ID --repo ALIAS --mode review --base BASE --head REVISION` через `KIT/scripts/kit.py`. Для обновления origin-веток явно используй `--fetch`; недоступную ревизию не заменяй другой. Дополнительные репозитории подключай тем же ID по необходимости.
3. Если симптом зависит от незакоммиченных изменений или локальных данных, исследуй исходную копию только на чтение и отметь ограничения. Не делай вид, что worktree на HEAD воспроизводит локальное окружение. Не читай `.env` и секретные файлы.
4. Выполни investigate-bug: воспроизведение, гипотезы, доказательства, альтернативные причины и план проверки исправления. Сохрани полный отчёт вне worktree в выбранной папке Obsidian, а в `PROJECT/.engineering-kit/runs/ID/report.md` при необходимости оставь локальную ссылку; для исследования без worktree также выбери уникальный ID.
5. Заверши исследование отчётом. Если пользователь поручил исправление, согласуй значимый план и используй процедуру реализации из `KIT/skills/plan-feature/SKILL.md` с новым ID и режимом feature: не смешивай detached-ревью с веткой реализации.
6. Для ненужных worktree предложи очистку по `KIT/skills/workspace-cleanup/SKILL.md`. Отчёт сохраняется. Если исследование не создавало worktree, очищать нечего.
