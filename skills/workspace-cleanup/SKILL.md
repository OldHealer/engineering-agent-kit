# Завершение и очистка

Разреши символьную ссылку на этот файл; корень kit (`KIT`) находится на два каталога выше его папки. Прочитай `KIT/AGENTS.md` и соблюдай правила целевого проекта.

При доступном `kit-git` прочитай `KIT/agents/integrations.md` и используй `kit_git_status`, `kit_git_cleanup_preview` и `kit_git_cleanup` вместо команд shell ниже. Передавай те же ID и согласованный токен, `idle_confirmed=true`, `confirm=true` только после согласия. Остальные проверки сохранности и запрет удаления текущей рабочей папки остаются обязательными.

Если status/preview отмечает задачу как current, объясни, что временного worktree нет: исходную папку удалять нельзя. Не предлагай обход блокировки, удаление файлов приложения или реестра. Полные отчёты остаются в Obsidian, локальное служебное состояние и ссылки — в runs.

1. Установи проект. Выполни `python3 KIT/scripts/kit.py status --project PROJECT`: без ID команда перечисляет зарегистрированные задачи. Если пользователь не выбрал задачу, предложи выбор; не очищай все папки автоматически.
2. Выполни `cleanup --project PROJECT --id ID` без `--confirm`. Это предпросмотр всего набора: пути, HEAD, ветки, блокировки и токен состояния. Покажи точные пути удаления, что останется в сохранённых ветках и каталоге результатов. Не выдавай токен за согласие пользователя.
3. При любых блокировках ничего не удаляй. Изменения надо сохранить отдельно по запросу пользователя. Игнорируемые файлы также блокируют очистку: не считай их автоматически мусором и не читай содержимое секретов. Не делай автоматический stash/commit/push, не применяй `--force`, `rm -rf` и удаление веток.
4. До удаления убедись, что полные отчёт/план сохранены в Obsidian по `KIT/skills/feature-hub/references/artifacts.md`, вне worktree, и больше не нужны локальные файлы. Ссылка из Obsidian на удаляемый документ не является сохранением. При незавершённом копировании сначала заверши передачу владельцу, не удаляй папку. Останови собственные запущенные проверки. Спроси, завершены ли другие сессии/сервисы, использующие эти папки: помощник не может достоверно определить их занятость. Если текущая сессия запущена из удаляемой папки, сначала перенеси работу штатным способом или попроси запустить очистку из корня проекта; не удаляй текущую рабочую директорию сессии.
5. Получив явное подтверждение точных путей и отсутствия активной работы, выполни `cleanup --project PROJECT --id ID --confirm TOKEN --idle-confirmed`. Токен бери из согласованного предпросмотра. Если состояние изменилось, снова покажи предпросмотр и запроси подтверждение нового состояния.
6. Сообщи, какие папки удалены и где остались результаты. Ветки и ссылки с коммитами сохраняются, поэтому worktree можно создать заново. При частичном отказе Git покажи фактическое состояние через status: уже удалённое фиксируется в реестре, оставшееся не удаляй обходным способом.

Очистка не запускается по таймеру. Удаление worktree удаляет его локальные файлы; пользовательские локальные файлы могут быть невосстановимы, поэтому обход блокировок не поддерживается.
